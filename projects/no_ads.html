CleanSearch

네이버 블로그에서 제품·장소 후기 검색 시, 대가성 광고(협찬)를 AI로 탐지·필터링해 순수 실사용자 리뷰만 제공하는 웹 서비스

Overview

맛집이나 제품 후기 검색 시, 법적으로 대가성 광고 여부를 명시해야 하지만 사용자가 포스팅을 직접 열어봐야만 알 수 있었습니다. CleanSearch는 검색 결과 단계에서 광고를 선제적으로 탐지·필터링해 진정한 사용자 리뷰만 보는 경험을 제공합니다.

기술 해결 과제: 단순 텍스트뿐 아니라 이모티콘·이미지 형태로 위장된 광고까지 탐지. Image Hash + OCR + 키워드 다중 매칭으로 다각화된 필터링 파이프라인 구축했습니다.

진행 중

핵심 기능

1 이미지 해시 필터링 — 광고 배너 이미지의 해시값을 저장해 동일하거나 유사한 이미지 자동 탐지
2 이모티콘/스티커 대응 — 광고를 이모티콘 형태로 위장한 경우 이미지 블록 추출 후 해시 비교
3 OCR 키워드 매칭 — EasyOCR로 "협찬", "지원받아", "소정의 원고료" 등 광고 키워드 다중 크로스 체크
4 네이버 블로그 API 스크래핑 — 사용자 키워드 기반 본문 자동 수집 및 분석
5 클린 리뷰 결과 출력 — 광고 필터링 완료 후 웹 인터페이스로 순수 리뷰만 표시

필터링 파이프라인

데이터 흐름: 사용자 키워드 입력 → 네이버 블로그 API 본문 스크래핑 → 이미지/이모티콘 추출 & 텍스트 파싱 → Image Hash 비교 + OCR 키워드 매칭 → 광고 포스팅 필터링 → 클린 리뷰 결과 출력

개선 진행 중: URL 단위 데이터 스트리밍 반환, 경량 OCR 모델 벤치마킹, UX 개선(로딩 페이지 인터랙션)

기술 과제 & 해결

문제 1: 이모티콘 위장 광고 탐지 — 초기에는 이미지 해시 비교만으로 충분하다고 가정했지만, 실제 데이터에서 이모티콘/스티커로 위장된 광고를 발견. 해결: 이모티콘을 이미지 블록으로 추출해 다시 해시 비교하는 방식으로 대응력 확보.

문제 2: 연산 병목으로 인한 느린 응답(30초~1분) — 데이터 스크래핑 + OCR 처리의 순차 처리로 인한 레이턴시 발생. 개선 액션: URL 단위 결과 스트리밍 반환, 경량 OCR 모델 도입, UX 개선으로 체감 시간 단축 중.

배운 점: 야생의 데이터(Wild Data)가 얼마나 다양한 변수를 포함하는지 체감했고, 좋은 AI 모델만큼이나 서비스 성능(레이턴시)과 UX가 중요함을 깨달았습니다.
