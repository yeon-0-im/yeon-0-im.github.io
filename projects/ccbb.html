Overview

CCBB는 블랙박스 영상을 분석하여 교통사고 과실 비율을 판단하는 멀티모달 AI 시스템입니다. Vision + RAG + 상용 AI 모델 파이프라인을 거쳐 종합적으로 추론합니다. 영상 분석 부분에서는 객체 탐지(차량/보행자 감지)와 영상 분류(사고 장소·유형·차량 행동 등 4단계) 모델을 사용했습니다.

(탐지 0.65 FPS, 분류 ~4.5초/stage). 데이터 확보 불가능(수백 GB)과 패키지 버전 충돌 제약 속에서, 교사 모델의 추론 결과로 학습 데이터를 자동 생성하고 속도 병목만 제거한 경량 학생 모델을 학습하는 역할을 맡았습니다.

최종 결과: 탐지 모델 66% 축소, 분류 추론 53배 가속으로 Jetson Xavier에서 실시간 운영 가능한 수준을 달성했습니다.

Role & Work (Vision 경량화)

1 Knowledge Distillation 설계 — 데이터 확보 불가 환경에서 교사 모델(Cascade R-CNN + SlowFast)의 추론 결과를 pseudo-label로 변환해 학생 모델(FCOS + SlowOnly) 학습 데이터 자동 생성
2 탐지 모델 경량화 — Cascade R-CNN의 RFP(3회 반복 순전파) → FPN, 3-stage RoI → FCOS anchor-free로 변경해 716 MB → 240 MB 달성
3 분류 모델 구조 단순화 — SlowFast(이중경로) → SlowOnly(단일경로), 8개 모델 → 4개 모델로 구조 최적화
4 ONNX → TensorRT 양자화 파이프라인 — numpy 타입 에러 우회를 위해 SlowFastWrapper 설계해 ONNX 변환 성공, TRT FP32 엔진 빌드로 분류 추론 53배 가속
5 Restrict Vector 캐스케이드 구현 — 원본 파이프라인의 4단계 분류(장소→유형→B차량→A차량) 제약 조건을 재현해 불가능한 클래스 조합 제거
6 Jetson 환경 최적화 — ARM(aarch64) 환경에서 Dynamic INT8 양자화 시 qnnpack 엔진 필수 설정, CUDA/PyTorch 버전 호환성 검증

경량화 파이프라인 (Vision 담당)

문제: 원본 모델 탑재 불가 (탐지 0.65 FPS, 분류 ~4.5s/stage) + 데이터 수신 불가 + 양자화 버전 충돌

해결: Knowledge Distillation으로 교사 모델이 직접 데이터 생성 → 속도 병목만 제거한 학생 모델 학습 → ONNX/TRT 양자화

결과: 탐지 66% 축소 + 분류 53배 가속 → Jetson에서 실시간 운영 가능

경량화 성능 비교

탐지 모델: Cascade R-CNN 716 MB → FCOS 240 MB (−66%)

분류 모델: SlowFast × 8개 258 MB → SlowOnly × 4개 242 MB + TRT로 추론 78ms/stage (기존 4,500ms 대비 57배)

전체 파이프라인: 기존 18초 → 340ms (53배 개선)

Stage별 정확도: Stage1 92.5% | Stage2 85.0% | Stage3 100% | Stage4 62.5% (클래스 불균형 이슈)

배운 점 & 회고

멀티모달 AI의 실무능력을 실감했습니다. 개별 모델만으로 도메인 학습된 탐지 + 분류 모델의 성능에 가까울 정도로 강력한 의사결정이 가능했습니다. 보완할 지점은 분명히 존재했지만, '오컴의 면도날 법칙'처럼 가장 단순하고 비용 효율적인 방법을 적용하는게 맞는지에 대한 고민이 생겼습니다.

환경 제약 속에도 문제 해결을 향한 도전의 가치를 깨달았습니다. 학습시킬 여건이 안되고, 양자화도 막힌 상황에서 Knowledge Distillation이라는 우회로를 찾아 교사 모델이 Pseudo-Labeling을 통해 증류하도록 설계한 경험은, 기술적 제약 속에서도 대안을 찾는 역량을 길렀습니다. 특히 팀원이 yolo-labeling으로 문제를 해결한 사례를 보고, 더욱 다양한 문제해결 방법이 있음을 배웠습니다.

MMCV 버전 호환성 이슈로 인해 어려움을 겪었습니다. MMDetection, MMAction2, MMDeploy 간의 버전 의존성이 복잡했고, Jetson CUDA 12.6과 PyTorch 1.13의 조합에서 라이브러리 충돌이 반복적으로 발생했습니다. 조합에 맞는 whl을 찾아서 계속 시도해보는 방법 밖에 없었습니다. 유지보수를 위해 dependencies, requirements의 중요성과 패키지 설치 파일에 대한 정보의 필요성을 느꼈습니다.
